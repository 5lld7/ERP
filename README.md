# مدار — نظام إدارة أعمال عربي

تطبيق ERP جديد مبني على مخطط الأقسام المرفق: الحسابات، المخازن والفروع، المعاينات والمبيعات، والموارد البشرية. واجهة RTL متجاوبة، وقاعدة بيانات مشتركة، وعمليات تُرحّل في معاملات ذرّية. يعمل محليًا بقاعدة SQLite، أو على Vercel مع قاعدة Turso دائمة. هذه نسخة جديدة من وصف الصورة، وليست استعادة لملفات النظام السابق الذي لم يوجد في المستودع.

**للنشر على Vercel:** راجع [دليل الربط والنشر](docs/VERCEL.md). ملفات النشر مدرجة، وتحتاج إضافة قاعدة Turso ومتغيرات الاتصال إلى حسابك.

## التشغيل

المتطلبات: Python 3.12 أو أحدث مع `venv`. لا يتطلب Node أو خدمة قواعد بيانات مستقلة.

```bash
cd /workspace/ERP
bash scripts/install.sh
bash scripts/start.sh
```

الخادم المحلي يستمع على المنفذ `8000` افتراضيًا. افتح التطبيق في متصفح على نفس جهاز التشغيل. أنشئ اسم الشركة وحساب المدير من شاشة البداية؛ لا توجد كلمة مرور افتراضية. للتشغيل على منفذ آخر:

```bash
bash scripts/start.sh --port 8080
```

على جهاز آخر بعد تنزيل المشروع، انتقل إلى مجلد المشروع بدل مسار `/workspace/ERP`. على Windows أنشئ `.venv` بواسطة Python، وثبّت `requirements.txt` بنفس خيارات التحقق، ثم شغّل `server.py` بواسطة `.venv\Scripts\python.exe`.

## أول دورة عمل

1. أدخل بيانات الشركة من الإعدادات، ثم الفروع والمخازن والوحدات والأصناف.
2. أضف موردًا وعميلًا. يمكن إنشاء عميل باسم «مبيعات نقدية».
3. أنشئ فاتورة مشتريات مع المخزن والأصناف. «حفظ وترحيل» يزيد المخزون ويُسجّل التزام المورد والضريبة. «حفظ كمسودة» لا يغيّر الأرصدة.
4. أنشئ معاينة وعرض سعر، وحدّث حالتها حتى الموافقة، ثم حوّلها إلى فاتورة مبيعات. أو ابدأ بيعًا مباشرة من نقطة البيع.
5. البيع يخصم الكميات ويُسجّل المبيعات وتكلفتها ورصيد العميل. سجّل الباقي من تفاصيل الفاتورة بواسطة «تسجيل سداد».
6. أضف الموظفين ورواتبهم، وسجّل الحضور والإجازات والمكافآت والسلف، ثم أنشئ مسير الشهر مرة واحدة. راجع أثره من كشف الرواتب وميزان المراجعة.

زر «تحميل بيانات تجريبية» يظهر للمدير عند خلو البيانات. التحميل اختياري، ويُنشئ سجلات حقيقية في قاعدة البيانات الحالية. ابدأ بقاعدة بيانات منفصلة للتجربة، ولا تخلطها ببيانات شركتك.

## التحقق

```bash
.venv/bin/python -m unittest discover -s tests -v
node --check static/app.js  # اختياري إذا كان Node متاحًا
```

تغطي الاختبارات المخزون والحسابات والمرتجعات والرواتب والصلاحيات والنسخ الاحتياطي والمرفقات وQR. لا تستخدم قاعدة بيانات شركتك.

اختبار الواجهة الاختياري يحتاج Playwright وChromium. في بيئة Codex الحالية هما متاحان عبر Python النظام و`/usr/bin/chromium`:

```bash
python3 tests/browser_smoke.py --screenshots /tmp/erp-screenshots
```

يختبر التسجيل الأول، والبيانات التجريبية، وإضافة صنف، والشراء، والبيع، والتحصيل، والرواتب، والتقارير، والتصفح من شاشة هاتف. يشغّل خادمًا مستقلًا وقاعدة مؤقتة.

## حدود التكامل

الدفع بالبطاقة والتحويل يسجّلان عملية سداد تمت خارجيًا؛ لا يخصمان أموالًا من بطاقة أو بنك. الربط الفعلي ببوابة دفع، أو جهاز حضور، أو الفاتورة الإلكترونية الحكومية يحتاج مزوّدًا وبيانات ربط محددة. التقارير الضريبية هنا تقارير حسابية للقيمة المضافة، والرواتب لا تحسب ضرائب الدخل أو التأمينات المحلية تلقائيًا. يُحدد الرصيد السنوي وساعات العمل وسياسة الخصم في الإعدادات، وتُراجع قواعد الشركة والقوانين المحلية قبل الاعتماد التشغيلي.

الخادم الحالي مناسب للتطوير والاستخدام المحلي. نشره لمستخدمين عبر الإنترنت يحتاج خادم تطبيق/بوابة أمامية بـHTTPS وضبط النسخ خارج الجهاز وحجم العمل. [دليل التشغيل](docs/OPERATIONS.md) يشرح ذلك.
