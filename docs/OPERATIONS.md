# دليل التشغيل والحفظ

للاستضافة على Vercel استخدم [دليل Vercel وTurso](VERCEL.md). تعليمات تشغيل الخادم الدائم والنسخ كل 24 ساعة أدناه تخص النسخة المحلية؛ وظيفة Vercel تستخدم قاعدة خارجية ولا تشغّل عامل نسخ دائمًا.

## الملفات المهمة

```text
erp.py                   منطق الأعمال والجداول والتقارير
server.py                HTTP API والمصادقة والصلاحيات
backups.py               النسخ المتسق والاحتفاظ بالنسخ التلقائية
seed.py                  بيانات تجريبية اختيارية
static/                  الواجهة العربية والإنجليزية بدون أدوات بناء
tests/                   اختبارات العمليات وHTTP والمتصفح
scripts/install.sh       تثبيت قابل للتكرار وتهيئة الجداول
scripts/start.sh         تشغيل الخادم في المقدمة
.local/erp.sqlite3       قاعدة بيانات هذه البيئة (غير مدرجة في Git)
.local/backups/          النسخ الاحتياطية (غير مدرجة في Git)
```

الشيفرة والوثائق والاختبارات قابلة للحفظ في Git. قاعدة البيانات والملفات الشخصية والجلسات والنسخ وبيئة Python مستثناة من Git ومن ملف تسليم الشيفرة المضغوط. لا توجد حسابات أو أسرار مُضمّنة.

## اختيار اللغة

زر **English / العربية** موجود في شاشة الدخول وشريط الأدوات داخل النظام، ويبدّل اتجاه الواجهة تلقائيًا. يُحفظ الاختيار في المتصفح لكل جهاز، ولا يغيّر بيانات الشركة أو أسماء العملاء والأصناف. تتبع النماذج ورسائل التحقق والتقارير والطباعة وتصدير CSV اللغة المختارة. عند تغيير اللغة داخل نموذج غير محفوظ، يطلب النظام تأكيد إغلاقه؛ حقول شاشة الدخول تبقى مؤقتًا في الذاكرة ولا تُحفظ في التخزين المحلي.

ترجمات الواجهة في `static/locales/en-ui.json` وترجمات بيانات التعريف في `static/locales/en-data.json`. القيم الداخلية للحالات والقوائم تبقى ثابتة لتوافق البيانات السابقة. لا تترجم أسماء وبيانات المستخدمين تلقائيًا. رسائل API تتبع `Accept-Language: ar` أو `en`، ويقبل التصدير `?lang=ar` أو `?lang=en`.

لاختبار اللغتين بقاعدة مستقلة:

```bash
node tests/i18n_engine.test.js
python3 tests/browser_bilingual.py --entrypoint vercel
```

## متغيرات التشغيل

| الاسم | الافتراضي | الاستخدام |
| --- | --- | --- |
| `ERP_DATA_DIR` | `.local` داخل مجلد المشروع | مجلد قاعدة بيانات منفصلة؛ يفضل مسار مطلق |
| `ERP_HOST` | `127.0.0.1` | عنوان الاستماع؛ لا تعرض الإعداد الأول للعامة بدون ضوابط نشر |
| `ERP_PORT` | `8000` | المنفذ |
| `ERP_COOKIE_SECURE` | غير مضبوط | اضبطه `1` عند الوصول عبر HTTPS لكي تصبح كوكي الجلسة Secure |
| `ERP_BACKUP_INTERVAL_HOURS` | `24` | الفاصل بين النسخ التلقائية، وصفر يعطّل العامل |
| `ERP_BACKUP_RETENTION` | `14` | عدد النسخ التلقائية المحتفظ بها؛ اليدوية لا تُحذف بواسطة العامل |

التثبيت يجلب `qrcode==8.2` وSDK الرسمي `libsql==0.1.11` من PyPI مع SHA-256 مثبت و`--require-hashes`، بدون تعطيل TLS أو التحقق من الحزم. الاتصال المحلي الافتراضي يستخدم SQLite من مكتبة Python القياسية، والاتصال البعيد يستخدم SDK. نطاقا التثبيت المطلوبان `pypi.org` و`files.pythonhosted.org` ضمن قائمة مديري الحزم المتاحة في البيئة.

## بيئة تجربة مستقلة

```bash
ERP_DATA_DIR=/workspace/erp-demo-data bash scripts/start.sh --port 8001
```

أنشئ حسابًا محليًا لهذه القاعدة واستخدم زر البيانات التجريبية. العودة لمجلد البيانات الأصلي تعيد شركة البيئة الأصلية. لا تحذف قاعدة الشركة لبدء تجربة.

## النسخ والاستعادة

ينشئ الخادم نسخة تلقائية عند بدء التشغيل ثم كل 24 ساعة افتراضيًا، ويتحقق من `quick_check`. العامل يعمل فقط أثناء تشغيل عملية الخادم. يحتفظ بآخر 14 نسخة تلقائية، ولا يدوّر النسخ اليدوية. النسخ في نفس الجهاز لا تحمي من فقد الجهاز؛ نزّل نسخة للجهة المسؤولة عن الحفظ خارج البيئة.

من الإعدادات يمكن تنزيل لقطة متسقة فورًا، تشمل بيانات الموظفين ومرفقاتهم. أو شغّل:

```bash
.venv/bin/python backups.py --retain 14
```

لا تنسخ ملف `erp.sqlite3` وحده أثناء نشاط الخادم؛ قد تكون معاملات حديثة في WAL. آلية النسخ تستخدم SQLite Backup API وتضمها.

لاختبار نسخة بدون المساس بالأصل:

```bash
mkdir -p /workspace/erp-restore-check
# استبدل المسار التالي بنسخة حقيقية، والمجلد الهدف بمجلد جديد وفارغ.
cp /path/to/verified-backup.sqlite3 /workspace/erp-restore-check/erp.sqlite3
ERP_DATA_DIR=/workspace/erp-restore-check bash scripts/start.sh --port 8002
```

اختبر تسجيل الدخول والتقارير في النسخة المستعادة. الاستعادة الفعلية: أوقف الخادم، احتفظ بقاعدة البيانات الحالية وملفات WAL/SHM في أرشيف قابل للاسترجاع، واستخدم مجلد بيانات جديدًا يحتوي النسخة المتحققة. لا تستبدل قاعدة مفتوحة.

النسخ تتضمن حسابات المستخدمين وكلمات المرور المشتقة والجلسات الموجودة وقت النسخ. احفظها بصلاحيات وصول مناسبة، وأعد ضبط الحسابات أو الجلسات عند استعادة بيئة لأشخاص آخرين.

## نشر استخدام فعلي

- الخادم هنا خادم تطوير من مكتبة Python. قبل نشره للإنترنت اختر بوابة أمامية ومدير عمليات مناسبين، وفعّل HTTPS و`ERP_COOKIE_SECURE=1`، وثبّت اسم النطاق وضوابط الوصول. لا تثق بترويسات proxy واردة من الإنترنت مباشرة.
- أنشئ المدير الأول قبل فتح الوصول العام، ثم مستخدمًا مستقلًا لكل مسؤول قسم. الدور «مشاهدة عامة» يشمل الأرصدة والرواتب والمرفقات.
- قيّم حجم البيانات وعدد المستخدمين والكتابات المتزامنة. SQLite WAL مناسب لنسخة محلية/فريق صغير؛ الفروع الكثيفة قد تتطلب قاعدة بيانات وخادم إنتاج مختلفين.
- سجلات تشغيل الخادم لا تطبع أجسام الطلبات أو الكوكيز. سجل العمليات التجاري متاح في الإدارة، لكنه ليس سجلًا خارجيًا محميًا ضد مسؤول قاعدة البيانات.
- الإعداد الحالي لا يرسل رسائل أو فواتير لجهات خارجية، ولا يستهلك خدمة دفع أو API مدفوعة. كل الربط الخارجي يحتاج تطويرًا وإعدادًا منفصلين.

## Codex وحفظ العمل

استخدم checkout الموجود في `/workspace/ERP`؛ كل مهمة سحابية معزولة بالفعل، فلا تنشئ Git worktree إلا بطلب صريح. تحقق من حالة Git ومحتوى الفرع قبل نشر المشروع. حفظ الشيفرة في المستودع، وحفظ بيئة Codex، ونشر الموقع على Vercel عمليات مستقلة؛ تحقق من نتيجة كل واحدة.

تعليمات التثبيت والتشغيل محفوظة أيضًا في مسودة إعداد البيئة. نشر البيئة في واجهة Codex يحفظ لقطة الملفات والتبعيات؛ لا يُفترض استمرار العمليات المفتوحة، ولذلك يجب إعادة تشغيل `scripts/start.sh` في المهمة الجديدة والتحقق من رد API ومن السلوك المطلوب. حفظ المسودة وحده ليس نشرًا ولا تحققًا من استعادة مهمة جديدة.
